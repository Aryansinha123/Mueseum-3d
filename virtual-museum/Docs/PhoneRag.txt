# Add AI Curator + RAG to Mobile AR Mode

## IMPORTANT

The laptop/desktop Virtual Museum is already working correctly.

The existing system includes:

* 3D museum environment
* Space, History, and Natural History galleries
* 3D GLB artifacts
* Artifact selection
* Rotate / zoom / interaction
* FastAPI backend
* RAG retrieval
* Confidence/relevance threshold
* Grok API
* Grounded AI answers
* Source/evidence display
* Session memory
* Related artifact recommendations
* Refusal for out-of-scope questions

DO NOT rebuild or replace the existing RAG system.

DO NOT create a separate AR-specific RAG system.

The goal of this task is:

> **Make the exact same AI Curator + RAG system available inside Mobile AR Mode when an artifact has been placed in the real world.**

The laptop museum must continue working exactly as it currently does.

# 2. CORE REQUIREMENT

When the user places an artifact in AR, that artifact must become the currently selected artifact.

For example:

```text
User opens AR
        ↓
Selects / places Morse-Vail Telegraph Key
        ↓
AR scene contains ART003
        ↓
Current AR artifact = ART003
        ↓
User presses "AI Curator"
        ↓
Curator knows ART003 is being viewed
```

The artifact ID must come from the actual artifact data.

Do not hardcode:

```text
ART003
```

Use the actual selected/placed artifact ID dynamically.

# 6. SEND THE AR ARTIFACT ID TO `/ask`

This is the MOST IMPORTANT requirement.

When the user asks:

```text
"What is this?"
```

the frontend must send something like:

```json
{
  "session_id": "sess-123",
  "question": "What is this?",
  "artifact_id": "ART003",
  "tone": "educational"
}
```

The exact artifact ID must come from the currently placed AR artifact.

NEVER send:

```json
"artifact_id": null
```

when an artifact has been successfully placed.

NEVER send a fake ID.

# 9. CONTEXTUAL QUESTIONS MUST WORK

When a valid `artifact_id` is supplied, questions such as:

```text
What is this?
Tell me about this.
What am I looking at?
What is this artifact?
Tell me more about it.
Why is this important?
What is it made of?
When was it created?
Where is it from?
What was it used for?
```

should be interpreted in the context of the selected AR artifact.

For example:

```text
AR artifact = ART003
Question = "What is this?"
```

should NOT perform a generic semantic search for the phrase:

```text
"What is this?"
```

Instead:

```text
artifact_id = ART003
        ↓
resolve ART003
        ↓
retrieve artifact knowledge
        ↓
ground Grok answer in ART003
```

---

# 10. DO NOT BYPASS THE RELEVANCE GATE

Important:

Having an artifact selected does NOT mean every question should be answered.

For example:

```text
Artifact = Morse-Vail Telegraph Key

Question:
"What is the weather today?"
```

must still be rejected if weather information is not in the curated knowledge base.

The selected artifact is contextual information.

It is NOT permission to answer unrelated questions.

Maintain the existing confidence/relevance/refusal logic.

---

# 11. REFUSAL MUST WORK IN AR

For an unrelated question:

```text
What is the weather today?
```

the AR curator should show:

> This information is not available in the curated museum knowledge base.

The response should still contain the existing fields:

```json
{
  "answer": "This information is not available in the curated museum knowledge base.",
  "source": null,
  "confidence": 0.21,
  "evidence": null,
  "refused": true
}
```

Do not call Grok when the existing gate says the query should be refused.

---
