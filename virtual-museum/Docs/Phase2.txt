==================================================

1. CORE OBJECTIVE
   ==================================================

The system must prevent the LLM from answering questions that are
outside the curated museum knowledge base.

The pipeline must be:

USER QUESTION
↓
EMBED QUESTION
↓
COSINE SIMILARITY
↓
BEST MATCHING ARTIFACT
↓
SIMILARITY / RELEVANCE CHECK
↓
┌─────────────────────┐
│ score >= threshold? │
└─────────┬───────────┘
YES │       │ NO
↓       ↓
LLM CALL   REFUSAL
↓
GROUNDED ANSWER
↓
Answer + Source + Score + Evidence

IMPORTANT:

The threshold check MUST happen BEFORE the LLM call.

If the score is below the threshold:

* Do NOT call the LLM.
* Do NOT generate an answer using general knowledge.
* Return the fixed refusal response.

==================================================
2. CONFIDENCE / RELEVANCE THRESHOLD
===================================

Create:

backend/rag/confidence.py

Define a configurable threshold.

Example:

THRESHOLD = 0.55

However, do not describe 0.55 as a scientifically proven value.

Call the value:

retrieval threshold
or
relevance threshold.

Do NOT claim that a similarity score of 0.55 means
"55% confidence".

The score is cosine similarity.

Make the threshold easy to change from one place.

Example:

THRESHOLD = 0.55

Create a function such as:

is_relevant(score)

which returns:

True / False

==================================================
3. REFUSAL BEHAVIOR
===================

If:

similarity_score < THRESHOLD

return a structured result without calling the LLM.

Use this exact default message:

"This information is not available in the curated museum knowledge base."

The result should contain:

{
"answer": "This information is not available in the curated museum knowledge base.",
"source": null,
"confidence": similarity_score,
"evidence": null,
"refused": true
}

Use the field name "confidence" in the final API-style response if useful,
but internally make it clear that this value originates from retrieval
similarity and is not a calibrated probability.

==================================================
4. ACCEPTED QUERY BEHAVIOR
==========================

If:

similarity_score >= THRESHOLD

then:

1. Select the best matching artifact.
2. Extract its description.
3. Extract artifact name.
4. Extract gallery.
5. Send ONLY the necessary information to the LLM.

The LLM must receive:

* user question
* retrieved artifact information

Do not send the entire artifact database to the LLM.

==================================================
6. STRICT GROUNDING PROMPT
==========================

The LLM system prompt must enforce:

"You are an AI curator for a virtual museum.

Answer the user's question ONLY using the supplied curated
artifact information.

Do not use outside knowledge.

Do not invent facts, dates, names, measurements, historical
events or interpretations.

If the supplied artifact information does not contain enough
information to answer the question, explicitly state that the
information is not available in the curated knowledge base.

Keep the answer concise, clear and suitable for a museum visitor."

Then provide:

ARTIFACT INFORMATION:
{artifact description}

USER QUESTION:
{user question}

IMPORTANT:

The model must not receive the full artifact database.

It receives only the retrieved artifact.

==================================================
7. SOURCE INFORMATION
=====================

source:

{
"artifact": "...",

}

Do not fabricate source information.

==================================================
8. EVIDENCE
===========

Every accepted answer must return an evidence field.

The evidence must come directly from the retrieved artifact
description.

Do not ask the LLM to invent the evidence.

Use the original retrieved text.

Example:

"evidence": "This ceramic vessel dates to approximately 1500 BCE..."

For Phase 2, it is acceptable to return the complete relevant
description as evidence rather than implementing sophisticated
sentence-level highlighting.

The frontend can later highlight it.

==================================================
9. FINAL PIPELINE
=================

Create:

backend/rag/rag_pipeline.py

Implement the complete Phase 2 flow:

answer_question(question)

Process:

1. Validate question.
2. Retrieve best artifact using Phase 1 retrieval.
3. Obtain similarity score.
4. Compare score against threshold.
5. If below threshold:
   return refusal
   DO NOT call LLM.
6. If above/equal threshold:
   call grounded LLM.
7. Return:

   * answer
   * source
   * confidence/similarity score
   * evidence
   * refused flag

Expected successful structure:

{
"answer": "...",
"source": {
"artifact": "...",
"gallery": "..."
},
"confidence": 0.82,
"evidence": "...",
"refused": false
}

Expected refusal structure:

{
"answer": "This information is not available in the curated museum knowledge base.",
"source": null,
"confidence": 0.21,
"evidence": null,
"refused": true
}

17. RESEARCH TERMINOLOGY
========================

Use these terms correctly:

"retrieval similarity score"
rather than automatically calling it a probability.

"relevance threshold"
for the decision boundary.

"grounded answer"
for an answer generated from retrieved artifact information.

"refusal"
when the system rejects a query because retrieval similarity
is below the threshold.

Do not claim that the system completely eliminates hallucinations.

The correct research claim is that the architecture is designed
to reduce unsupported responses by gating LLM access and
restricting accepted responses to retrieved evidence.
